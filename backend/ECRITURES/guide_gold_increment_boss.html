2. Le modèle Gold (Star Schema)

TableTypeRôle
dim_agencesDimensionRéférentiel des agences (stable, UPSERT)
dim_clientsDimensionRéférentiel des clients (stable, UPSERT)
dim_dateDimensionCalendrier (généré une fois)

Point clé : Les dimensions et la fact utilisent UPSERT car elles peuvent contenir des données existantes qu'on met à jour. Les agrégats sont en full refresh car ils sont petits et rapides à recalculer.

3. Qu'est-ce que UPSERT et pourquoi ?

UPSERT = UPDATE + INSERT. En PostgreSQL :

INSERT INTO dim_clients (id, nom, segment, encours, score, statut)
VALUES ('CLI-10001', 'Hassan Ouazzani', 'Particuliers', 525523.36, 66, 'Actif')
ON CONFLICT (id) DO UPDATE SET
    nom = EXCLUDED.nom,
    segment = EXCLUDED.segment,
    encours = EXCLUDED.encours,
    score = EXCLUDED.score,
    statut = EXCLUDED.statut;
Explication :
- Si CLI-10001 n'existe pas → INSERT
- Si CLI-10001 existe déjà → UPDATE (on remplace les valeurs)
- EXCLUDED = la ligne qu'on essaie d'insérer
- Résultat : zéro doublon, même si on lance le pipeline 100 fois

Avantages :

  • Idempotence garantie
  • Prêt pour de l'incrémental
  • Pattern standard en production
  • Compatible avec tous les moteurs SQL (MERGE dans SQL Server, MERGE INTO dans Databricks)

6. Détail de load_gold.py (tu codes ça)

Ce que fait ce fichier :

  • Crée les tables Gold si elles n'existent pas
  • Insère les données avec UPSERT
  • Les agrégats en full refresh (TRUNCATE + INSERT)
  • Optionnel : créer la table dim_date avec une année de dates

6.1 Création des tables

-- dim_agences
CREATE TABLE IF NOT EXISTS dim_agences (
    id VARCHAR(50) PRIMARY KEY,
    nom VARCHAR(100),
    ville VARCHAR(50),
    region VARCHAR(50),
    directeur VARCHAR(100),
    telephone VARCHAR(20),
    email VARCHAR(100),
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- dim_clients
CREATE TABLE IF NOT EXISTS dim_clients (
    id VARCHAR(50) PRIMARY KEY,
    nom VARCHAR(100),
    segment VARCHAR(50),
    encours DECIMAL(15,2) DEFAULT 0,
    score INTEGER,
    statut VARCHAR(50),
    email VARCHAR(100),
    telephone VARCHAR(20),
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- fact_engagements
CREATE TABLE IF NOT EXISTS fact_engagements (
    ref VARCHAR(50) PRIMARY KEY,
    client_id VARCHAR(50),
    client_nom VARCHAR(100),
    type_credit VARCHAR(50),
    montant DECIMAL(15,2),
    duree INTEGER,
    taux DECIMAL(5,2),
    score INTEGER,
    statut VARCHAR(50),
    date_depot TIMESTAMP,
    agence_id VARCHAR(50),
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- agg_kpis_agence
CREATE TABLE IF NOT EXISTS agg_kpis_agence (
    agence_id VARCHAR(50),
    agence_nom VARCHAR(100),
    mois VARCHAR(7),
    nb_engagements INTEGER,
    encours_total DECIMAL(15,2),
    montant_moyen DECIMAL(15,2),
    score_moyen DECIMAL(5,2),
    PRIMARY KEY (agence_id, mois)
);

6.2 La requête UPSERT (la plus importante)

INSERT INTO dim_agences (id, nom, ville, region, directeur, telephone, email, updated_at)
VALUES (:id, :nom, :ville, :region, :directeur, :telephone, :email, NOW())
ON CONFLICT (id) DO UPDATE SET
    nom = EXCLUDED.nom,
    ville = EXCLUDED.ville,
    region = EXCLUDED.region,
    directeur = EXCLUDED.directeur,
    telephone = EXCLUDED.telephone,
    email = EXCLUDED.email,
    updated_at = NOW();

Même pattern pour dim_clients et fact_engagements.

6.3 Agrégats : full refresh

-- Étape 1 : vider
TRUNCATE TABLE agg_kpis_agence;

-- Étape 2 : insérer les nouveaux calculs
INSERT INTO agg_kpis_agence (agence_id, agence_nom, mois, nb_engagements, encours_total, montant_moyen, score_moyen)
SELECT
    f.agence_id,
    a.nom,
    TO_CHAR(f.date_depot, 'YYYY-MM'),
    COUNT(*),
    SUM(f.montant),
    AVG(f.montant),
    AVG(f.score)
FROM fact_engagements f
JOIN dim_agences a ON f.agence_id = a.id
GROUP BY f.agence_id, a.nom, TO_CHAR(f.date_depot, 'YYYY-MM');
